## [Unreleased]

- Rename (#159 candidate): the product name `majed` is retired; every owned identifier now uses the `waycraft` prefix (CSS classes and variables, data attributes, settings/slot/panel ids `waycraft-skills` and `waycraft-subscriptions`, locale namespaces, RPC routes `/api/waycraft-subscriptions.*` and `/api/waycraft-skills.catalog`, header `x-waycraft-skills`, localStorage keys, the `__dshWaycraft` hook, the font route, the collision-fallback tool names `dsh_waycraft_*`, the user agent `dsh-waycraft`). Storage moves to `plugins/waycraft/subscriptions/` and `~/.dsh/waycraft-skills/`: on first start missing files are copied (staged, atomic, never overwriting, symlinks not followed; file modes are kept, but credential files `auth.json`/`proxy.json` are masked to owner-only 0600 at most). The migration never modifies or deletes the old files, which are read as a fallback when a single-file copy fails; if the skills-root copy fails (or the legacy tree exceeds 20000 entries / 512 MiB) the skills manager keeps reading and writing the legacy root, which is therefore updated by normal use. For ONE release the host still answers the old RPC routes, skills route/header and font route, the browser still reads the old localStorage keys, keeps `window.__dshMajed` as an alias, maps a saved old active panel id, and keeps the old tool view keys for old transcripts. Not renamed yet: the Loader row ids `majed`, `majed-subscriptions`, `majed-skills` in `cordis.patch.yml` (pending Owner verification of the effect on enabled state), and the old collision-fallback tool names `dsh_majed_*` are not kept as aliases. Previously generated image files in the old `images/` directory are neither copied nor read; rollback after use may need a re-login (token refresh writes only the new `auth.json`); a new client with an old host is unsupported (restart the host and reload the page together). Details, rollback and removal plan: `docs/ai/rename-waycraft.md`. Earlier entries below keep the old names as history. Host restart and page reload required; verified against local fixtures only, not an installed app or a real data upgrade.

- Skill manager (#156 candidate): repository and catalog installs can now target a registered project's DSH skills folder through the destination picker (listed as "<project> — DSH" next to DSH and Shared Agents). The same skill can be installed in several scopes/projects; each copy keeps its own provenance and is uninstalled to Trash, restored, updated and rolled back independently, with no global or cross-project fallback (a mismatched project is rejected with `project-mismatch`). The host re-resolves the project from the workspace registry on every action and refuses unregistered, unavailable or symlink-escaping destinations; a project that leaves the registry shows its copies as unavailable and they can be forgotten (record only). Existing user-scope records are unchanged. Verified against local fixtures only; host restart required. Projects that share a folder name are told apart by a parent-folder suffix; the pickers list unavailable projects as disabled options with the reason, preview the destination folder with a commit-visibility note, show an empty-projects hint and keep Install disabled until a valid destination is selected.

- Skill manager (#155 candidate): add a Discover Skills scope (sub-tabs Git Repos / ClawHub / skills.sh; the former Repositories scope now lives under Git Repos) with ClawHub popular browsing (download ranking, 10 per page, up to 100 items; sorting by installs or name and the status filter only affect displayed items), ClawHub search and skills.sh search (search only, no browse), details with a read-only copyable SKILL.md, and a confirmed install into the user DSH or Shared Agents folder (never project scope). Catalog endpoints are fixed https hosts (no redirects, 15 s timeout, 1 MiB answer cap, content-type and JSON-shape validation, 60 s bounded cache); packages are downloaded through the bounded archive extractor (files, bytes, path traversal, links) before a staged install that records catalog id, download URL and package digest. Uninstall asks for confirmation (with a shared-agents warning when the copy lives in the Shared Agents folder), moves the copy to Trash with exact restore; a record whose location is gone can be forgotten after a confirmation (Forget removes the record only); an identical untracked copy can be adopted (reassociate). Catalog version updates are intentionally not offered. Limits: page size 10 (cap 100), query 100 characters, 1 MiB per text answer, 8 MiB / 100 files per package, 2000 recorded installs. Known limitation: a catalog hostname is checked once before the request resolves it again, so DNS rebinding in between is not prevented (endpoints are fixed host configuration). For skills.sh JSON packages only, file paths with dot-prefixed segments, non-ASCII characters or spaces are refused (ClawHub zips accept dot files); catalog text drops bidi marks, zero-width space and BOM but keeps ZWNJ/ZWJ. A record whose Trash entry was removed outside the app can be forgotten (record only). English and Arabic UI; ranking, search and install were tested only against local stubs, not the real ClawHub or skills.sh.

- Skill manager (#154 candidate): tracked repository installs show update-available and locally-modified states (a locally edited copy that also has an update shows both, and the Repositories status filter "Update available" includes it) and preview added/removed/modified files before changing anything. Applying an update or rolling back is bound to the previewed digests (a changed repository, copy or backup is refused with a stale-preview error), needs explicit consent to replace local edits, stages the replacement, keeps the previous version as a backup and restores the original on any failure; rollback returns to the retained previous version. Exactly one backup is kept per install: the next update replaces (auto-deletes) it, and Forget record and permanent deletion from Trash remove it. If automatic recovery fails the operation reports `repo-recovery` with the folder that keeps the original files (do not repeat the operation); a cleanup failure after a successful change is reported as a warning, not an error. Success is announced (role=status) and progress is shown while applying; a skill removed, renamed or invalid upstream is shown on the installed row; the preview region has an accessible name and file paths are left-to-right isolated in Arabic. Tracked attributes: only file contents and the executable bit are compared and restored (a `chmod +x` edit counts as a local edit); empty folders, timestamps, ownership and other permission bits are not tracked and are not preserved by update/rollback (the preview says so). Pending Owner disposition (#157 parity): resetting a locally modified copy whose upstream is unchanged to upstream, and collecting orphaned backup folders left by a crash. Available in English and Arabic.
- Skill manager (#153 candidate): add Repositories — subscribe to GitHub (`owner/name` or URL), supported HTTP(S) Git and local repositories with ref and subdirectory; bounded scan, filter and single/bulk refresh with progress and errors (a failed refresh keeps the previous usable snapshot); tracked user-scope install (DSH or Shared Agents) with typed snapshot provenance (Git commit vs GitHub archive fingerprint vs folder fingerprint), no-overwrite conflicts and stale-snapshot refusal; uninstall to the #151 Trash with provenance that survives restore; unsubscribe leaves installed files and their source attribution. Git runs by argv `spawn` with hardened options; loopback/private/reserved hosts (including IPv6 forms that embed or alias them: IPv4-mapped/compatible, NAT64, 6to4, Teredo, site-local, documentation, `198.18.0.0/15`, `192.0.2.0/24`), credentials, non-HTTP(S) schemes and redirects are refused. Archive extraction is sliced and limit-checked as it inflates, so an expansion bomb stops early with `repo-limit`; `repositories.json` is size-capped at write time (`repo-limit`, state unchanged) and deeply validated on read (names, ids, hashes, destination roots), so a hostile repository or a tampered file cannot poison or redirect existing subscriptions and installs. The Repositories view has status and repository filters, a confirmation before unsubscribing, shows install/uninstall cleanup warnings and marks name conflicts (`<name>` and `<name>.md`) per destination. English and Arabic. Requirements and limits: Git and local-Git sources need the system `git` executable (GitHub archives and plain folders do not); cleartext `http://` Git hosts are allowed by design (public hosts only; credentials in URLs are refused); `Config.repositories` (git binary, archive base URL, `allowPrivateHosts`, limits) is a trusted host-code seam, not user input. Persisted repository state survives restarts for everything the app itself writes (including skills over the per-skill file limit, flagged `repo-skill-limit`); a subscription URL is capped after normalization; if a destination folder changes, tracked installs show "Destination changed" (English/Arabic) without being read or removed while subscriptions stay usable. Such a stale record can be forgotten ("Forget record" with a confirmation, English/Arabic; record-only, no files are read, moved or deleted) and uninstall reports the dedicated `repo-invalid-root` instead of a read-only error. Saved state is validated against fixed maximum sizes rather than the configured limits, so lowering `maxEntries`, `maxRepositories`, `maxInstalls` or `maxStateBytes` between restarts never makes existing subscriptions unreadable (they stay readable, removable and uninstallable; only new growth is refused), and repository source fields (ref, subdirectory, URL, owner/name) are re-validated on load so a hand-edited state cannot redirect a refresh outside the repository. IPv6 SIIT addresses embedding private IPv4 are blocked. Residual risk, not fixed: the public-host check resolves the name once and Git resolves it again (DNS rebinding between the two is possible without a connect hook). Not a catalog (#155) or project-scoped repository install (#156); content update and previous-version rollback arrive with #154; parity items are tracked for #157.
