## [Unreleased]

- Implement #133 Grok subscription provider and account card, Grok image generation/edit fallback alongside the existing Codex pool, video generation and X search, durable media read endpoints and inline image gallery/lightbox/video views in English and Arabic. Worktree-only implementation; independent review and Owner consolidated live acceptance remain pending. No installed changes.

- Fix the second #132 review finding: an imported Claude account now stays in sync when the `claude` CLI refreshes first. A rotated Claude Code login is adopted by account identity (email, compared case- and whitespace-insensitively) instead of by refresh-token continuity, because real Claude Code credentials usually carry no email and the refresh token changes on every refresh; a missing email is resolved with the account profile lookup (bounded, cancellable) and recorded on the imported account. When the identity cannot be proven (another account, lookup failed, offline) nothing is adopted and Claude Code's store is not written. Import attempts a profile request when email is missing; refresh-time identity checks can also request profiles with the stored and/or source access token when their emails are missing. Host change: full DSH restart. Sync with a real Claude Code login is not live-verified.
- Fix #132 review findings: Claude now registers through the preference-aware adapter, so display names, model visibility and renaming, independent-account entries and pooling reach the picker and chat, and Claude accounts join the account pool; an imported Claude account stays synced with Claude Code after the first refresh (`keychainBound` is preserved); a different account signed in to Claude Code is never adopted or overwritten (a new account needs an explicit import); disposing the component stops in-flight sync work and aborts a pending token refresh; the credentials-file writer refuses symlinks. Corrected the Owner steps. Host change: full DSH restart.
- Add the Claude subscription to the Subscriptions component (#132): connect Claude by browser authorization or by importing the existing Claude Code login (the imported account stays in sync with Claude Code's own store), chat with Claude models, see Claude usage in the card and the composer badge, and choose the prompt cache lifetime (follow config / 5 minutes / 1 hour) in the Manage dialog. English and Arabic. The Claude card disappears when the component is off; with reference enabled it can remain visible but shared-provider collisions prevent simultaneous serving, and composer surfaces withdraw; a Claude failure does not affect Codex, the Settings section or core dsh-majed. Candidate only: no real Claude account, import or inference was used; Owner live acceptance pending.
- Contain render failures of the composer surfaces (#131 hardening): the usage badge, Speed control and the Settings display control are wrapped in an owned error boundary, so a vanished or changed host primitive removes only that one surface and logs `dsh-majed: <surface> failed to render`, instead of relying on the host slot boundary. Browser half only: reload the page.
- Add the Subscriptions composer surfaces (#131): a usage badge in the composer that shows the default account's quota for the current subscription and expands into every account and window (with a Settings control to show recent usage or hide it), a Speed control (Standard / Fast) next to the composer and a `/fast` command, both shown only for Codex models whose catalog advertises a fast tier. Host endpoints `majed-subscriptions.speed` and `majed-subscriptions.setSpeed` (the explicit choice is per session and resets on restart; subagents keep their saved default). All surfaces appear only while the component is on and the reference plugin is not serving, in English and Arabic (RTL). Automatic usage reads never force a refresh. Host changes need a full DSH restart; the browser half needs a reload.
- Close the remaining #130 boundaries: upstream OAuth failures (reset credits, registration, login) reach the browser only as status and code; provider settings are saved as an atomic field-level patch and proxy writes are serialized, so concurrent clients no longer lose each other's changes; model, context-limit and account discovery reads are bounded by a 10 s deadline and the caller's cancellation, advertised context bounds use the minimum across accounts and invalid `context_window` values are ignored. Limits: unknown bare secrets in non-OAuth text cannot be detected, and two clients editing the same field are last-writer-wins.
- Harden the diagnostic text returned by Proxy and Manage RPC errors (#130): the text is bounded before any work and sanitized in linear time (the former key pattern cost ~16 s on 128 KB of repeated `password`). Known stored/draft secrets are removed in raw, URL-encoded, form, JSON-escaped, base64 and `user:password`/Basic spellings; URL userinfo of any scheme, quoted and unquoted `Authorization`/`Proxy-Authorization` values (Bearer, Basic, Token, Digest, ...), bare `Bearer`/`Basic` credentials, cookies, `pwd`/`passphrase` and sensitive JSON members (whole arrays and objects, escaped and embedded JSON) are redacted structurally. Text too complex to sanitize within a fixed work budget is replaced by a generic message. Credentials and transport are unchanged; unknown secrets without a recognisable shape cannot be detected. Independent re-review and installed acceptance remain pending.

- Fix the final #130 review findings: a hung account no longer fails pool assembly (per-account bounded reads, healthy accounts still serve), `proxyTest` validates its payload and draft before any network use, `force` must be a boolean on `providerSettings`, `modelDefaults` and `usage`, `modelDefaults` returns the reference per-provider model catalog (with `force` refresh), quoted and nested JSON secrets are redacted from diagnostics, disposing the component aborts in-flight proxy tests and releases the resident password, and pool settings are validated by a schema (`strategy`, `switchMargin` >= 1, defaults). Drop the unused `dsh-agent` dev dependency. The Codex image tool, Codex web search and image pool are recorded as pulled forward from #133.
