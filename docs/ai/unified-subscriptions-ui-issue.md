## Confirmed surface brief

- **Job / mode:** Operate. The Owner scans their configured model access, adds a provider/account and manages existing access without navigating separate API and subscription inventories.
- **Selected direction:** Native DSH settings authority, code-led. Page title/intro, one top **Settings** disclosure for general Proxy / Pool / usage-display controls, one mixed configured-provider list, then exactly one **Add model provider** entry point. The first viewport prioritizes real provider identity/type/status/account count, not a hero or dashboard metrics. Provider-specific **Manage** stays inside its provider card.
- **Signature interaction:** The Add button is replaced IN PLACE by an inline panel with **Third-party API**, **Custom API**, **Subscription** choices. It is not left beside the open panel, not a modal, and not a second subscription-add surface. Cancel and complete success restore the button and focus. Pending authorization, validation, settings conflicts and partial writes do not pretend completion. Retain visited drafts while switching safe modes; clear sensitive drafts on cancel/success. Lock conflicting mode changes while an operation is pending; cancellation must respect the existing auth controller and distinguish UI close from completed cancellation.
- **Subscription path:** Choose provider, then expose only its supported login/import/callback/device-code controls inline. Successful account admission updates one grouped provider card/count; expanding reveals accounts, real quota windows and existing account actions. Adding another account uses this same workflow, optionally preselected from the provider card. Zero-account providers remain selectable in Add rather than five permanent empty onboarding cards. Pending auth remains recoverable. Zen stays a clearly labeled loginless provider lane within the unified list, not a fake account/login option.
- **Bounds:** ONLY the owned `majed-subscriptions` section. Native Settings > Models, its navigation/services/child slots and onboarding remain untouched. Prior replacement research and concept image are historical evidence only. No Models shadow, CSS hiding, nav replacement, host patch or private runtime import. Existing secondary Manage/destructive confirmation dialogs are preserved; the no-modal requirement specifically governs Add/auth entry, not removal of safety confirmations.
