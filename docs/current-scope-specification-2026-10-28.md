# dsh-majed: six-family current-scope specification

Date: 2026-10-28. **Local review draft — not published, ticketed, implemented or accepted by this document.** Behavioral authority: Owner decisions through Q134; testing boundaries approved by Q135. This synthesis awaits Owner review before tracker publication and ticket reconciliation. No operational permission is implied.

## Problem Statement

The Owner wants one coherent DSH experience instead of separate reference plugins for appearance, subscription access, Skills, MCP and Hooks. Existing Majed capabilities and controlled proofs are useful investments, but neither isolated helpers nor test counts establish a complete usable workflow. Important native-consumer and operational gaps remain.

The Owner needs ordinary development to proceed without repetitive command prompts, while destructive actions and sensitive access keep their proper boundaries. Accounts, model defaults, search and media must be understandable without conflating login, capability, payment, permissions or Auto enrollment. Optional routing should continue work safely when a route is unavailable, not replay uncertain work or change context behind the Owner's back. Local and paired interfaces must show the same authoritative execution state while retaining personal display preferences.

The approved redesign also includes the complete reviewed dsh-claude-style capability set under Appearance, not a selectively reduced subset. Desired coverage must remain explicit where platform, licensing or public-extension support is unresolved.

## Solution

Deliver one versioned plugin with isolated feature modules and native DSH Settings, in this priority order:

1. DSH Enhancements, including full Appearance and session command auto-approval.
2. Subscriptions, including six provider targets, native API model references, search, image generation/editing and video.
3. MCP Manager.
4. Skills Manager.
5. Hooks Manager.
6. Auto & Smart Routing.

Retain working behavior and preferences rather than rebuilding everything. References are learning sources, not required runtime companions. Native public extension points, permissions, actual model identities and session ownership remain authoritative. Standalone Tool Rules is excluded and source-disabled; this neither removes MCP per-tool controls nor disables native guards or Command Hooks.

A capability is complete only when its actual production consumer exhibits the required behavior at the applicable evidence layers. Missing public contracts remain named dependencies until supported alternatives or explicit Owner dispositions exist. Design agreement never silently defers a requirement.

## Implementation Decisions

### Shared ownership and scope

- Deliver one plugin with isolated independently enabled modules, common native Settings/admission/presentation and explicit disposal. Follow the priority order without treating it as an invented dependency graph. Reuse complete working slices and their tests; missing consumers still need integration.
- Use public DSH extension points only, respecting accepted architecture decisions and the glossary. Native services are allowed dependencies; external reference plugins are not. Preserve authenticated Owner admission over both local and paired transports; origin/custom headers alone are not authentication. Bound management inputs/responses, use no-store handling and redact failures.
- Separate profile-local presentation from host-owned accounts, execution settings and managed definitions, scoped policy, native session choices and native API configuration. Host-owned state uses private, atomic, serialized/conflict-safe persistence and recovery; private permissions are not encryption or protection against the same OS user. Secrets never return in browser snapshots or default diagnostics. Never access another plugin's operational store implicitly.
- Login, saving, installation, availability, routing membership, tool permission, Hook Approval and activation are separate states. Cross-client updates do not resend work. UI wording distinguishes saved, enabled, pending, observed and unsupported state rather than fabricating success.
- Keep ordinary workflows simple; advanced safety bounds remain internal/advanced rather than proliferating settings. Preserve every approved capability. Document missing implementation, controlled proof, unverified exact-host behavior, unsupported public contract and explicit Owner deferral as distinct statuses.

### DSH Enhancements

- Preserve saved/native appearance initially; expose the entire approved reference set without activating every visual change. Appearance groups cover User Stories 6–19, including folding/navigation beyond screenshot-only coverage. Keep platform-only settings visibly unavailable with explanation, and preserve essential click/touch/keyboard alternatives.
- Explicit font family wins over theme typeface styling. Brand/palette changes preserve family, size and Arabic fallback; native/theme-font selection remains available. UI size range is 11–20, default 14, distinct from native chat sizing; retain current bundled/system family choices without adding a font-download manager. Content direction remains independent of UI language.
- Custom brand/name preferences are profile-local; validate supported local image formats before display. They neither rename provider accounts nor publish/upload images automatically. Display changes preserve composer text, accessibility and reading position, and cannot dispatch tasks or switch accounts. Hidden sidebar entries remain in More; native search/permissions/data and archive-versus-delete semantics remain intact. Account-hold is an explicitly optional demo/joke, never real suspension/payment UI.
- Experimental rendering starts off with warnings, a reliable path back to native styling and disclosed style-plugin conflicts. No automatic disabling of another plugin. Desired renderer/asset features remain subject to path-specific licensing and supported extension proof, not literal copying assumptions.
- Currency/custom prices affect displayed estimates only. Missing prices/usage are unknown; native figures, estimates, provider charges and subscription allowances remain distinct. These settings never control routing, payments or quotas.
- Retain bidi/menu grouping on, copy-on-select off, background-only notifications and completion/intervention on as defaults unless a saved preference overrides them. Reset affects only that preference/profile, takes effect visibly and does not request OS permission or reset accounts/features. Command-mode reset can only reduce authority to Ask me.
- Notifications deduplicate per interface/event during continuous connection, independently per enabled device. Foreground notifications are silent; background sound follows OS settings without competing sound or Do Not Disturb bypass. Off suppresses session-event alerts except explicit tests. System alerts omit conversation/command/file content and session title by default; title inclusion is opt-in. No closed-page mobile-delivery promise. Navigate to the actual session; report OS permission/fallback honestly.
- Copy-on-select excludes inputs/composer/terminal, preserves native mobile selection controls and confirms actual clipboard success only. Native page reading delegates authorized reading to native web fetching with cancellation, bounded/truncated raw content, no implicit summary/query processing or cloud fallback; retrieved material is untrusted.

### Session command auto-approval

- Ask me is the default for new sessions and host restart. Safe/Aggressive are one authoritative session setting shared across authorized interfaces, not browser-local authority. Refresh/reconnect reflects actual mode and cannot restore stale local permissions. Missing supported synchronization is a decision gate, not permission to simulate it.
- Safe permits scoped routine work: reads/edits, branches/commits, known-effect tests/build/dependencies, ordinary trusted-project pushes and regenerable temporary cleanup. It checkpoints materially destructive/hard-to-reverse work such as deleting an unmerged branch or dropping a database. A checkpoint affects that request, not selected-mode persistence; independent work may continue. There is no arbitrary three-handback shutdown.
- Aggressive additionally permits known-target task-authorized destructive project actions, including specified rollback/data deletion. It retains native security, sensitive-data restrictions and explicit task prohibitions, with clear enablement warning. Neither mode grants unrelated-target authority or Keychain/key exposure. Mode answers native command permission requests, not blanket browser/MCP/other-tool permission or Command Hook Approval.
- Fixed rules make definitive local decisions first. Contextual evaluation, when enabled, uses an explicitly chosen supported judgment connection/model; optional reuse with Smart does not merge activation/policy. Explicit local-only operation is supported with honest coverage. Never pick the chat model or fail over accounts/services silently.
- Send only necessary action/task/boundary/reversibility context, never collected secrets or full transcripts automatically. One judgment attempt per request; adjustable default deadline 20 seconds, optional session call cap, no monetary-budget guarantee. Unavailable/timeout/invalid response uses reviewed mode-specific local fallback, then a request-specific human checkpoint if unresolved. Fallback cannot override a substantive refusal/checkpoint.
- Fallback entries constrain effects/targets/paths, not just command names. Safe defaults match routine work above; Aggressive includes Safe plus reviewed project-risk cases. Owner customization belongs in trusted Settings; project/agent content and one-off approval never expand persistent authority. Scripts/compound commands require known relevant contents/effects; an innocuous wrapper name does not establish safety.
- Revalidate relevant mode/policy/request/script/target changes and fence late responses after cancellation/resolution; never duplicate execution. Show redacted origin/reason/intervention and call counts. Keep the last 100 decisions in host memory only, clear on session closure/restart, and retain no raw commands, outputs, sensitive paths or raw judgment responses. Confirm monetary cost only with reliable evidence.

### Subscriptions, API references, search and media

- Deliver complete provider workflows: actual provider-specific authentication/refresh, protected durable state, restart reload, native model catalog and prepared account-bound dispatch. Codex is the existing first complete-workflow foundation; remaining five targets retain distinct protocols rather than synthetic auth/catalog substitutes. OpenCode anonymous connection is not a fabricated account; authenticated methods remain separate where supported.
- **Adopt the reference Subscriptions experience (Owner decision 2026-10-29).** The Subscriptions feature takes the reference plugin's complete user-facing behavior as adapted source rather than a from-scratch redesign: per-provider cards with connection state and CLI/version note, per-account cards (default star, full email, plan, token expiry, sign-out), per-account Usage block (plan, refresh, quota windows such as 5-hour and weekly with percent used and reset time, expandable usage-limit/reset credits with explicit confirmed use), Add account and Manage actions, the Manage dialog (subscription display name, per-account alias, include in pool, independent model-picker entry, pool model allowlist, model list editing, cache TTL, provider tools) and the composer usage badge. Adding an account opens the provider's authorization page; the host-side loopback callback completes the login automatically and the page observes completion by polling status, while pasting a callback URL or code remains a fallback for browsers that cannot reach the host's loopback port. Adapt (do not rewrite) the reference client and host half, pinned to v0.9.11 (`7639ed9958a9a1c4159faa1f4e6e15e9ede60b7d`, MIT, the version the Owner observes); newer upstream releases are reviewed separately. Keep Majed's own protected private account store, public-extension-only mounting, no runtime dependency on the reference plugin (the Owner disables the installed reference plugin before installing Majed's; Majed never modifies `~/.dsh`), its own namespaced management routes so both can never collide, Arabic and RTL support, and the existing approvals gates. Preserve per-file attribution and the license notice in `THIRD_PARTY_NOTICES.md` and each module's provenance record. This does not authorize credential import from the reference plugin, live provider consumption or cutover.
- Preserve supported browser/device authorization, verified identity and cancellation/expiry/late-settlement fencing. Dedicated sensitive UI handles login. No silent credential import, replacement by a different identity, Keychain access, request disguise, IP rotation, local sidecar spawning or hidden fallback is adopted merely because a reference contains it. Any required mechanism needs explicit supported-path disposition.
- Successful login exposes eligible direct choices without selecting or invoking one. Chat enablement is separate; tools start off and routing/judgment participation requires explicit selection. Pause blocks new Majed requests across paths but retains login/settings; sign-out removes local credentials while retaining the card/settings; confirmed removal deletes card/settings, not conversations/results. Request cooperative in-flight cancellation, surface limits, and never claim local sign-out revoked the provider session.
- Host owns accounts, pause, activation and defaults across authorized clients; native session choices stay session-specific. Separate hosts do not synchronize accounts implicitly. Labels do not replace provider-verified identity; reject verified duplicates within provider/access method and offer explicit reconnection. Show the full account identity (e.g. email) on the authenticated Settings and usage surfaces (Owner decision 2026-10-29, superseding default masking there); credentials never appear, and diagnostics, logs and exports keep masking identities.
- Preserve aliases/visibility/defaults, independent account entries, direct/manual pooling, source-backed static/discovered/manual catalogs, model effort/context/output/modalities, cache TTL and supported Fast behavior. Metadata refresh may be on demand/periodic where supported with stale/source timestamps, but is not generation proof or Auto enrollment. Do not replace missing saved models or fabricate unsupported options/provider defaults.
- Plain pinned direct routes remain account-bound; manual pools remain distinct from Auto. Preserve normalized text/reasoning/tool/usage/error streams, complete attachment references, native offload rules, tool-result pairing and account/provider/model-bound opaque replay isolation. Never silently discard retained images/history or restore host-offloaded bytes. Count safe retries; ambiguity after sending or partial output requires visible recovery rather than account transfer, stitching or repeated effects.
- Preserve provider quota windows/resets and locally observed use as distinct figures, with source/freshness and unsupported/unknown states. Warning estimates alone do not exclude a working route. Retain explicit eligible reset-credit preparation/confirmation with single-use uncertainty protection, supported cache TTL, proxy/bypass and provider/client settings; prove settings affect actual traffic. Never mutate process-global network timing; a public module-scoped alternative or explicit timing-gap disposition is required. No automatic purchase of accounts/capacity.
- Search, image generation/editing and video keep independent activation and eligible service/account/model choices. Chat changes do not change them. Unsupported operations/settings receive visible errors/disposition, never an undisclosed substitute; image input is not generation or video support. Preserve established tool identities/aliases and history/policy semantics through native registration without duplicate owners; revalidate revoked activation before dispatch.
- Search sends the query/necessary context only, identifies sources/snippets versus summaries and missing citations, treats content as untrusted and distinguishes full-page reading. Never report model recall as retrieval. Images preserve selected ordered complete references, actual edit endpoints/options and originals; failed references do not become text-only generation. Retain durable outputs/native galleries and alias-compatible rendering where supported.
- Video/media exposes actual pending/running/finished/failed/expired/unknown states without invented percentage progress. Persist/recover job identity where supported; reconnect queries that job rather than resubmitting. Local cancellation differs from confirmed provider cancellation, with no assumed refund. Temporary links/download failures are explicit; downloads, restart or polling recovery never regenerate implicitly. Native playback/result cleanup must work locally and remotely.
- Native API configuration/credential ownership stays native. Consume eligible model references through verified public seams; no duplicate API provider manager or secret copy. Eligible API models are not limited to subscription brands. Manual, Auto/Smart and supported opted-in children use those identities under their respective boundaries, not universal-protocol/media promises. Subscription-to-API fallback needs explicit enrollment and usage-based-billing disclosure; connection setup alone grants neither spending nor fallback.
- Default diagnostics contain provider/operation/category/time/request ID where available, mask identities and exclude credentials/conversation/file/media content. Diagnostic export is explicitly requested, reviewable, redacted and never automatically uploaded. Ordinary conversation/result persistence is a separate concern.

### MCP Manager

- Use private Majed-owned definitions and isolated lifecycles. Prefer the native MCP client; an official SDK client may be used through verified public DSH APIs when required, retaining native scope/permissions, cancellation, normalized results and complete teardown. One owner per connection/tool registration; never concurrent native/SDK or reference ownership.
- Same-name project definition overrides global within that project only. Show provenance and effective selection; removing override discloses global fallback, without promoting configuration or leaking tools cross-project. Save new/imported definitions disabled. Connect/Test explicitly discloses stdio host-user execution or HTTP access, including remote initiation; saving never installs/downloads/launches.
- Validate active edits before replacing healthy state; dispose before reconnecting. Disable retains secrets/definition, blocks new calls and disconnects. Removal deletes only the scoped managed definition/secrets after effect disclosure. Best-effort cancellation is not rollback of external effects. Unrelated healthy servers survive failures; cleanup failures remain visible and prevent accumulating replacements.
- Provide selected-tools-only and all-except-denied. New servers default to selected-only: new tools stay excluded there, while all-except-denied applies its explicit policy to discoveries. Native permissions still decide authority; descriptions are untrusted. Changes in command/destination/tool authority require renewed review.
- Import/export previews formats, destination, scope, conflicts and unsupported semantics; no silent field loss/replacement. New imports stay disabled, exports omit secrets by default and indicate re-entry needs. No implicit another-plugin store read/takeover. Keep/replace/remove never returns stored values; empty fields do not erase them. Concurrent/external edits require review, and transport changes cannot silently reassign/delete credentials.
- Distinguish disabled/saved/connecting/discovery-success/failed/needs-login and last observed result/time; no invented continuous reachability. Bound Connect/Test/reconnect; refreshing status does not restart a failed server. Supported browser auth/relinking binds the correct host-side connection across remote/mobile clients without an implicit broker.
- Persist reviewed activation/tool policy: global reconnects after startup validation; project waits for matching runtime. Disclose persistent activation; changed external authority needs review and invalid state does not start. Disabled/new/imported definitions remain disabled.

### Skills Manager

- Use native discovery/Agent/preset/session and invocation semantics as authority, with explicit source, scope, writability and effective manual/model state. Require actual cold/warmed consumers and same-Agent preset switching, not just manager-list correctness. Unicode management preserves original names/bytes while separately diagnosing native invocation compatibility.
- Create/edit only in explicitly chosen writable sources; protect bundled/read-only/external originals and reject traversal/symlink escape. Availability differs from ownership, and global scope cannot bypass native Agent/preset policy. Enabling respects source manual/model denials and executes no instructions/scripts or account/tool activation.
- Show conflicting sources and native winner per context without silent merge/rename. Disclose fallback before disable/remove, with explicit name-wide exclusion in scope where supported and visible uncertainty. Reversible trash retains source/content/resources/policy; restore conflicts need review and permanent deletion needs confirmation. Read-only sources use availability controls, not deletion.
- Local file/folder imports and uploads preview metadata/files/destination/conflicts and supported semantics. Reject escaping paths, preserve supported resources, keep new imports disabled and execute/install nothing. Mobile folder support follows browser capability. Opt-in catalog/repository browsing shows source/revision/license where available; selected installs use reviewed owned destinations and disclosed network/download effects, never trust endorsement or activation.
- Local search/filter and labels/categories are management metadata, not instruction/identity/precedence changes or implicit paid/external semantic search. Manual/opt-in periodic update checks are separate from application; review instruction/resource/invocation changes, detect local edits, preserve recoverable previous content and never activate/broaden permissions. Missing comparison/pinning support is visible. Untracking a repository preserves installed files/provenance/labels/policy; outages never delete/substitute origins.
- Persist policy/labels/repositories with conflict-safe mutation and native restrictions. Disable/remove affects future supported loads, not retained instructions, completed effects or running tools. Edits/restores apply on subsequent supported loads; disclose refresh/new-session requirements rather than restart secretly or mutate conversations. Synchronization limitations need Owner disposition.

### Hooks Manager

- Retain compatible project/user definitions and separate Majed consent, without importing historical Approval. Legacy profile re-addition is manual, not automatic store import. Keep draft/review/Approval/activation separate; duplicates/imports start unapproved/disabled, and export excludes consent/secrets. Respect writable ownership and preserve other runners until approved Cutover.
- Require authenticated exact-version review, server receipt time, short-lived expiring single-use challenge and server-verified typed `RUN AS DSH USER` confirmation. Bind normalized command, canonical scope/cwd, environment and watched content; revalidate before queueing/execution and after waiting. Record local/remote only with trustworthy evidence, otherwise unknown. Display-only metadata changes neither grant nor require renewed execution consent. Execution-affecting changes invalidate it; Safe/Aggressive cannot substitute.
- Prove actual native mappings independently for SessionStart, UserPromptSubmit, PreToolUse, PostToolUse, PermissionRequest, Stop and PostCompact. Event JSON uses stdin only, with reviewed/minimized fields and no shell interpolation/full-transcript or secret collection. Commands run as the DSH OS user, not a sandbox; UI masking does not limit process access.
- Use visible bounded matchers and deterministic sequential order per event; global/project same-name definitions are independent with explicit exclusions. Effects are event-specific supported context/restriction/observation/Stop continuation, not arbitrary stdout instructions. Native guards always win; post-events cannot undo actions or recover discarded context.
- Observational/optional-context failure is visible and continues without claiming success. A configured pre-action gate's denial or invalid/missing result blocks that action, terminates the event chain and has explicit recovery; later Hooks cannot override it. Prevent recursion/incomplete structured results. Stop permits at most three continuations per actual user-started turn, not reset by a continuation.
- Bounds across Majed: four active commands, 64 queued, 30-second queue deadline, shared 300-second event-chain deadline. Per-command default 30 seconds, adjustable up to 300 seconds within the chain; per-run stdin 1 MiB, stdout 256 KiB, stderr 64 KiB. Same-event sequencing still applies. Lower bounds are allowed; increasing beyond reviewed limits requires explicit changes, not model/project authority. Overflow/expiry follows event failure policy visibly; these are limits, not a process-containment guarantee.
- Disable retains still-valid consent; revoke requires renewed review. Disable/revoke/delete fences new/queued work, requests best-effort active cancellation and discards result effects after relevant consent/policy invalidation. Propagate owning-operation cancellation where supported, distinguish requested/confirmed state and expose cleanup failure; no rollback or automatic interrupted-run retry.
- Restart restores activation only with scope/content validation; missing/changed/unverifiable definitions suspend visibly. Reconnect does not replay events, restored removals return unapproved/disabled and interrupted runs stay interrupted. Persist last 200 runs as metadata-first history, no default raw stdin/stdout/stderr; detailed diagnostics are opt-in with residual privacy warning. Redacted export/clear does not change Approval.
- Passive validation executes/downloads nothing. Explicit manual testing needs valid exact-version Approval, disclosed synthetic inputs and all runtime limits/cancellation; it may test a disabled definition but neither activates it nor applies outputs to live actions. It is real host execution, not a sandboxed dry run or proof of event wiring.

### Auto & Smart Routing

- Register one genuine native Auto identity. Never persist transient selection as a global default or fake a picker entry. Explicit candidates identify subscription account or native API connection, provider/model, priority, default and Smart-permitted effort. Login/catalog discovery is not membership; manual pools, search/media scheduling and child enrollment remain separate.
- Filter locally for permissions, explicit effort, tools/images, context/output and prepared capabilities before priority/judgment. Preserve all request content and explicit requirements; conservative capability claims and no-fit errors replace silent degradation. Model-sensitive prompt contributors, selected identity, effort and actual dispatch must be coherent before provider execution through a supported public contract.
- Use priority with healthy session stickiness. Recovered higher priorities do not displace healthy routes. Strategy/order edits apply to new sessions or explicit safe reapply; disabled/removed membership blocks new dispatch in all sessions, including after async preparation. Do not secretly cancel/replay in-flight work; manual selection exits Auto.
- Permit at most three distinct candidates per safe pre-output cycle with actual cross-layer accounting across owned pools/dispatch/outer retries, including explicitly characterized bounded auth refresh. No hours-long automatic waits. Distinguish account/model failure scopes, provider resets/local estimates and earliest known retry/unknown status. Missing usage or warnings, including 95%, do not alone exclude an otherwise eligible route; cancellation/input incompatibility are not account failures.
- Stop hidden switching at first non-usage output, including reasoning/tool fragments, or possibly completed effects. No stitched output or side-effect/media replay; close iterators and propagate cancellation. Visible partial-failure recovery is required rather than silent resend. Show actual account/model/effort and grounded route/fallback reason.
- Smart is independent optional task-suitability selection over a closed eligible model/effort set, not cheapest-by-default or permission ownership. Revalidate membership, availability, policy generation and explicit effort before application. Invalid/stale/unavailable/abstaining results use authorized priority. Evaluate at initial selection, explicit re-evaluation or route unavailability, not every message/tool.
- Owner explicitly configures a supported protocol/connection/model with secure settings; base roots and complete decision endpoints are distinct. Never access Jev/private credentials, assume the chat model or route the judge recursively through Auto. Optional connection reuse with command judgment leaves policies/activation and accounting attribution distinct; do not invent a universal shared budget across unrelated consumers.
- Require minimal-disclosure consent/per-session disable. Send bounded task text, opaque candidates and necessary capabilities; exclude account/file names, full history, secrets and MCP values. Explain residual sensitive text and external-retention risk. One judgment attempt per decision, default three-second deadline, no automatic retry/hidden service fallback; owning cancellation fences late results.
- Smart evaluation default cap: 20 per day across Majed, configurable, coherently accounted across concurrent sessions. Timeout/cap exhaustion falls back to priority; cap exhaustion applies for the rest of that day. Three consecutive service failures pause Smart evaluation for five minutes; legitimate abstention is not failure and Auto remains enabled. Request counts are not monetary guarantees. Preserve available actual model/usage/cost metadata without invented judge explanations or calibrated-confidence claims.
- Retain minimal local routing decision/fallback/timing/available-cost metadata for seven days with manual deletion, never raw tasks/history/judgment responses. Shadow is explicitly authorized, consumes declared judgment budget, compares proposal versus applied route without applying or executing twice, and cannot automatically activate Smart or establish quality.
- Children require independent explicit opt-in and verified supported pre-start route/effort seams; explicit child model/preset/permissions, native depth and concurrency win. No universal interception of external backends. Independent capability advice uses only currently authorized agent-visible Skills/MCP inventory, coordinates with Jev and never installs/enables/approves/changes credentials or reduces exposure. Neither advice nor Shadow is prerequisite for manual/Auto use.

## Testing Decisions

Q135 approves a single primary behavioral boundary: **Owner action in native UI → admitted production transport/service → actual native consumer → visible outcome**; event-driven behavior starts from actual native lifecycle. Reuse existing harnesses rather than building a second platform. Lower deterministic tests supplement races, parser cases, bounds and policy combinations that are impractical through the primary path. Test observable dispatch counts, effective availability, persisted state, denied effects, cancellation and disposal; helper-call or source-text assertions alone are insufficient.

Evidence layers remain separate: portable built-product regressions with temporary state; exact-version unmodified native controlled integration with synthetic pairing/providers; real rendered desktop/browser/mobile acceptance; separately authorized installed/account/provider/Cutover acceptance. No historical test total is a current acceptance result.

- Enhancements: built client/preference regressions plus actual session permission request/guard and cross-client host-state flow. Test every Appearance group and per-setting reset, saved/default/font precedence, Arabic, keyboard/touch, draft/reading position, motion/recovery and no unintended native action. Notification delivery/clipboard/geometry need real browser/OS evidence. Verify restart-to-Ask-me, judgment privacy/timeout/fallback, local-only decisions and stale/cancelled checkpoints.
- Subscriptions: reuse production Codex Settings/auth/store/catalog/prepared-adapter flow against controlled provider transports, then independently characterize each other provider's real protocol. Cover login/refresh race/cancel/revocation/remount, actual selected identity, options/usage/proxy, complete references and streamed error/replay behavior. Test native API reference integration without secret copies; count media submissions and same-job reconnect/restart recovery, aliases/galleries/playback, no hidden edit fallback and search citation honesty. Generation probes are distinct from catalog refresh.
- MCP: reuse mounted native Settings/admitted Fetch/actual MCP client/ToolRuntime with controlled stdio and HTTP. Add scope overrides/fallback, per-tool discovery policy, lossless import/export, secret operations/stale edits, restart review and supported auth/relinking. Check native permission denial, bounded probes, isolation and dispose-before-replacement.
- Skills: reuse production management/filesystem/native registry and actual Agent/tool/session slash consumers. Require cold and warmed availability, same-Agent preset changes and paired updates; cover source collisions, Unicode preservation/diagnostics, imports/resources, path safety, labels/repositories/updates and recoverable conflicts without activation or script execution.
- Hooks: join actual native lifecycle producer, composed approved definition and real bounded subprocess to the supported effect/history. Independently cover seven mappings, ordering, gate/observation failures, exact-version changes, queue waits/bounds, Stop count, restart/cancel/revoke/cleanup. Manual tests and synthetic SessionStart do not prove the other events or escaped-descendant containment.
- Auto: exercise actual native selection, model-sensitive assembly, prepared dispatch and visible route with controlled adapters. Count cross-layer attempts and verify partial reasoning/text/tool/effect boundaries, cancellation, revocation, stickiness, explicit efforts/images/context, cooldowns and API enrollment. A fixture-owned retry ledger or late redirect is not native coherence proof.
- Smart/children/advice: controlled protocol/clock/cancellation and actual consumers prove one attempt, deadline, daily cap/circuit behavior, concurrency, stale-answer fencing, privacy/retention, Shadow non-application, native child ownership and authorized-inventory-only advice. Optional quality evaluation needs an agreed task set/criteria and separate consumption permission; disagreement alone is not quality evidence.
- Common browser matrix: English and Arabic/RTL, light/dark, UI font 14/18, desktop/narrow viewport, keyboard forward/reverse focus and activation, scrolling/errors/dialog closure/focus return; add touch/platform scenarios where relevant. Test actual local/paired admission, not fabricated boot authentication. Dedicated historical UI verification obligations survive; functional failures become implementation work rather than cosmetic deferral.
- Normal package testing must include accepted new regressions and preserve baseline classification/read-page/preferences. Record built artifact, exact version, scenario, environment and redacted evidence for every acceptance claim. Release needs authorized restart/local/paired demos and reversible Cutover, not component totals.

## Out of Scope

- Standalone Tool Rules UI, mutation, reactivation or enforcement; retain legacy definitions inert for compatibility. Native guards, MCP per-tool policies and Hooks remain in scope.
- Host patching, private-method interception, replacement GUI servers, implicit profile/other-plugin takeover or runtime dependence on reference plugins.
- Automatic credential import/migration, Keychain/other-tool credential collection, hidden disguise/IP rotation/sidecars or account/provider spending merely because a reference uses them. Supported alternatives requiring them return for an explicit decision.
- Implicit enrollment, universal provider/media/protocol support, universal external-child interception, dynamic capability exposure reduction, automatic installation/activation, imported Hook Approval or automatic permission expansion.
- Observe-only SessionEnd/subagent Hook extensions and additional child backends beyond verified opted-in support remain separately deferred; advanced scheduling/broader Smart beyond the agreed strategy is not introduced here.
- New evaluation/replay platforms, ranking models by assumed price/quality, monetary guarantees from call caps, calibrated-confidence or zero-retention promises, and claims that the Owner's original rate-limit problem has already been diagnosed/fixed.
- Automatic external upload of diagnostics/brand data, reference deletion, installed rollout/restart, live/paid consumption, stable promotion or acceptance closure without the corresponding explicit approvals and evidence.

Local imports, repositories/catalogs, labels, reviewed Skill updates, MCP per-tool controls, reviewed Manager import/export and full Appearance are **included desired scope**. Historical first-release exclusions for them do not silently override the later redesign. Their old tickets/deferrals remain unchanged until approved reconciliation; no source gap is itself an Owner-approved deferral.
