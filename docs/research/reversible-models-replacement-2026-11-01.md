## 1. Public shadow registration and automatic registry rollback: supported

The [settings contract](/tmp/majed-models-proof-XZ46eh/settings/package/lib/types/client/contract/slots.d.ts#L62-L77) declares `settings.section` as a root-scoped list, `id` for navigation identity, `order` for position, `label` for display. Native Models registers `id: "models"`, `order: 10`, localized label, no explicit priority (therefore zero): [installed registration](/tmp/majed136-installed-source-aUugEO/dsh-client-ui-settings-models/lib/client.js#L4485-L4501).

The [published SlotCore registration](/tmp/majed-models-proof-XZ46eh/slots/package/lib/index.js#L163-L242) enforces:

- Same list id **and same priority** throws; default priority is zero. This is not last-writer-wins and cannot be resolved by load order.
- A different priority can reuse the same id; **lower numeric priority wins**. An illustrative `priority: -1` would outrank native zero, but arbitration with other replacements needs an explicit policy.
- Disposal removes only the exact registered entry, bumps versions and releases its owned resources; it does not remove the native entry.
- [entriesOfSlot](/tmp/majed-models-proof-XZ46eh/slots/package/lib/index.js#L263-L292) selects one live winner per list id; raw `entries` deliberately retains shadowed registrations.

The [renderer registry wrapper](/tmp/majed-models-proof-XZ46eh/renderer/package/lib/client.js#L1603-L1622) preserves disposal identity; [public register effect binding](/tmp/majed-models-proof-XZ46eh/renderer/package/lib/client.js#L1813-L1815) ties registration to the calling Cordis context. [Mutation notification](/tmp/majed-models-proof-XZ46eh/slots/package/lib/index.js#L553-L571) bumps versions synchronously and batches subscribers per microtask. The [outlet](/tmp/majed-models-proof-XZ46eh/renderer/package/lib/client.js#L1203-L1221) renders winner cells and honors `only` section selection.

Thus retaining native registration and disposing a Majed shadow is a supported **content registry rollback** without disabling settings, credentials or LLM. This does not yet establish correct navigation or feature preservation.

## 2. Hard blocker: settings navigation reads the raw ledger, not winners

The [published rc.3 settings shell](/tmp/majed-models-proof-XZ46eh/settings-general/package/lib/client.js#L1144-L1166) projects `ctx.slots.entries("settings.section")`, not `entriesOfSlot`, directly into navigation rows, sorts by order, and subscribes to ledger/locale changes. The [nav renderer](/tmp/majed-models-proof-XZ46eh/settings-general/package/lib/client.js#L303-L317) maps every row into a button keyed by `row.id`; it does not deduplicate ids. Its content outlet separately renders `only: active`: [content site](/tmp/majed-models-proof-XZ46eh/settings-general/package/lib/client.js#L335-L337).

Consequently keeping native Models alive and registering a different-priority `id: "models"` yields **two Models navigation rows, duplicate React keys and the same selected page**, even though only the Majed content cell renders. This fails the approved single replacement navigation acceptance criterion. Disposing Majed returns to one native row. A fresh `majed-models` id produces a separate page and gear icon, not the approved replacement.

The shell [icon mapping](/tmp/majed-models-proof-XZ46eh/settings-general/package/lib/client.js#L243-L268) hardcodes `models` to `IconDataOutlineMedium`, size 16; unknown ids get the settings gear. Reusing `models` preserves the desired icon and `order: 10` preserves position but triggers the duplicate-row problem. There is no inspected public nav-hide/suppress/deduplicate registration option. CSS hiding, monkeypatching `entries`, deleting another plugin's entry or shell replacement is not a supported fix under this contract.

**Minimal upstream prerequisite:** navigation must project shadow winners rather than raw registrations, or provide a documented reversible per-section presentation replacement contract that owns both nav and content. This is a proposed upstream correction/API, not authorization to patch DSH.

## 3. Independent hard blocker: native child slots remain owned by the native entry

Native Models owns `settings.models.provider-card` (root keyed) and `settings.models.footer` (root list): [installed children](/tmp/majed136-installed-source-aUugEO/dsh-client-ui-settings-models/lib/client.js#L4491-L4500). Shadowing content does not dispose the native registration or collapse its declarations.

A replacement cannot redeclare these children: [core validation](/tmp/majed-models-proof-XZ46eh/slots/package/lib/index.js#L191-L194) throws while any declaration is live. Omitting them avoids registration failure but does not authorize rendering them: the [renderer ownership guard](/tmp/majed-models-proof-XZ46eh/renderer/package/lib/client.js#L344-L349) rejects children absent from that entry's own declaration. [ctx-level renderSlot](/tmp/majed-models-proof-XZ46eh/renderer/package/lib/client.js#L1523-L1534) accepts only `root`, so it is not a public escape hatch for business child slots.

Native provider-card dispatch is keyed by **settings namespace**, with provider/configured/keyConfigured owner facts, and appears in setup, configured rows and catalog Add: [installed placements](/tmp/majed136-installed-source-aUugEO/dsh-client-ui-settings-models/lib/client.js#L2513-L2545), [configured dispatch](/tmp/majed136-installed-source-aUugEO/dsh-client-ui-settings-models/lib/client.js#L2615-L2620), [catalog dispatch](/tmp/majed136-installed-source-aUugEO/dsh-client-ui-settings-models/lib/client.js#L2706-L2729). Footer is after Add: [footer](/tmp/majed136-installed-source-aUugEO/dsh-client-ui-settings-models/lib/client.js#L2775-L2777). Existing third-party contributions would stay registered but become invisible in a shadow page that cannot render those locations. Copying their entries/components, retaining another owner's renderer, or hijacking its declaration is not a documented extension solution.

**Minimal additional prerequisite:** an upstream reusable Models content Factory/component with preserved child ownership, or documented child delegation/ownership-transfer semantics compatible with a retained fallback. Majed-owned child ids alone do not preserve existing contributions. Removing native Models to acquire its declarations violates the retained-fallback premise and risks onboarding; not proposed.

## 7. Host/client disable distinctions and remaining decisions

Native Models host half only publishes onboarding bootstrap configuration: [host source](/tmp/majed136-installed-source-aUugEO/dsh-client-ui-settings-models/lib/index.js#L1-L26). Client registration and refresh listeners have separate effects. Disabling a service component is NOT automatically equivalent to unloading the client effect. Majed currently can retain its section on a failing host-status envelope; only absence/404 withdraws it: [presence state](/Users/majedsiefalnasr/Documents/Work/DeepSeek%20Harness/dsh-majed-oauth-clean/src/browser.ts#L134-L158). A future replacement needs a precisely defined client registration lifetime and availability gate, not merely a host Loader toggle. No change to this lifecycle is approved or executed here.

Owner/lead dispositions needed:

1. Keep the full single-nav/function-preserving requirement and request upstream nav-winner projection plus a documented child-composition/delegation seam; this is the smallest supported direction, but upstream work needs separate approval.
2. Alternatively explicitly relax navigation and child-contribution compatibility for a separate Majed page. That is a different product contract, not fulfillment of this alternative. No DOM/shell/service-disable workaround is recommended.
3. Resolve the deliberate reuse of foreign `models` identity against Majed's all-owned-identifiers `majed` prefix policy: a narrowly documented replacement-cell exception would be needed. New child slots/effects/store ids still remain Majed-prefixed. Resolve priority collision/other replacements policy, native onboarding expectations, component versus whole-plugin disable behavior, and Globals/Proxy/Pool/Zen placement before implementation.

**Smallest next test seam, only if separately authorized:** obtain exact installed rc.3 shell/renderer/slots evidence read-only or pin a known public composition, then render the real published settings shell + renderer with fake Cordis/localization/remote faces. Assert one Models nav item, unchanged icon/order, Majed selected content while enabled, exact native fallback after disposal, child provider-card/footer continuity, locale changes, reconnect, enable/disable cycles and other same-cell priorities. The current public shell is expected to fail the one-nav assertion; do not build the full replacement before resolving that seam.
