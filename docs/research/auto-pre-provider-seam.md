# T02B: pre-provider model-selection seam audit

Date: 2026-10-23. Status: **source-research conclusion, not a runtime implementation or acceptance proof**.

## Conclusion

**No qualifying supported public seam was found in the inspected installed build.** The native loop does not dispatch an awaited, per-step model-selection event between claiming input and evaluating prompt providers. `system-prompt/assemble` is an awaited public transformation boundary, but it starts **after** variable, tool-schema, section-text and context-text providers have evaluated. `agent/pre-step` is later still. Neither listener registration order nor `prepend: true` moves either event ahead of provider evaluation. This conclusion follows from the complete local path through input claim, assembly and pre-step, not from event names. [Loop pre-step](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-agent-loop/lib/index.js#L902-L927>), [provider evaluation and waterfall](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-system-prompt/lib/index.js#L347-L405>), [middleware mechanics](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/cordis/lib/index.js#L308-L345>).

Public creation/setup and `agent/created` support initial composition before the driver runs. Public native `selectModel` supports explicit Session selection. Neither establishes the requested asynchronous, request-aware, before-every-provider selection transaction while preserving native Session-controller ownership. The accessible public pieces must not be presented as that missing combined contract. [Creation/setup](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-agent-loop/lib/index.js#L1914-L1955>), [awaited creation announcement](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-agent/lib/index.js#L565-L590>), [native selection](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-api-session-controller/lib/index.js#L788-L820>).

T02B therefore remains open at the full contributor-coherence/native-selection-ownership boundary. This is a finding about the surveyed installed implementation, **not** proof that every future release or unsurveyed extension can never provide such a seam. The earlier [partial Auto findings](<auto-native-seams.md#L48-L79>) already distinguish late interpolation/dispatch coherence from contributor coherence.

## 1. Exact per-step order

The native `preStep(target, position)` performs this sequence:

1. Read the turn signal and synchronously claim inbox input.
2. Await `systemPrompt.assemble(assembleContextFor(this, signal))`.
3. Check cancellation.
4. Dispatch the awaited `agent/pre-step` waterfall; its innermost default renders accepted runtime-context sections.
5. Return the accepted decision plus the already assembled prompt.

There is no other awaited dispatch between claim and assembly in this method. [Complete `preStep`](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-agent-loop/lib/index.js#L902-L927>). `assembleContextFor(agent, signal)` supplies `agent`, `scope: agent` and optional `signal`; it does not resolve a model or include the claimed batch. [Context helper](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-agent/lib/index.js#L284-L297>).

Inside `SystemPrompt.assemble(context = {})`:

- Global variable providers run first; scope-chain variable providers run next. Both are invoked synchronously as `provider(context)`.
- Effective section/context registrations are merged. Global tool providers, followed by scope-chain tool providers, are called synchronously and their schemas are copied.
- Effective sections are sorted and their text functions run. Effective context text functions run; tool ordering and the variables object complete the initial assembly.
- Only then is the scoped `system-prompt/assemble` waterfall awaited. Complete-section and runtime-context-suppression rules are enforced after that waterfall.

These statements are directly visible in the [entire assembly body](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-system-prompt/lib/index.js#L356-L405>) and [context-text resolver](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-system-prompt/lib/index.js#L183-L189>). Thus replacing returned interpolation variables cannot retroactively change model-sensitive provider text or schemas already evaluated.

This applies to the first proposed step and continuing steps: `turn()` repeatedly invokes `preStep`, initially with `next-turn`, then with `next-step`. It appends `turn/start` before the first proposal and `step/start` only after the proposal is admitted. Empty/rejected proposals can have already assembled providers without making a request. [Turn loop](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-agent-loop/lib/index.js#L937-L1009>).

## 2. Lifecycle candidates and why they do not supply the contract

### Input and status notifications

`claim(target, turn)` removes the next-step batch, optionally consumes one next-turn message, emits `agent/inbox/claimed` once for each claimed message, then returns the batch. It is not an async function and does not await those listeners. An input-free continuation has no message for which to emit a claimed event. [Inbox claim](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-agent-loop/lib/index.js#L97-L111>).

`agentEvents(...).emit` invokes listeners immediately and attaches rejection logging to their returned promises; it does **not** wait for those promises. Its `serial` and `waterfall` methods are distinct dispatch modes. [Agent dispatch implementation](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-agent/lib/index.js#L242-L272>). An async routing decision started by `agent/inbox/claimed` cannot hold provider evaluation until it settles. A listener's synchronous prefix does run before claim returns, but that is not an awaited, once-per-step admission contract.

Likewise inbox insertion publishes `agent/inbox/inserted` as an emit, before returning from mutation; `send` then wakes the driver. It describes queue mutation, not admission of the exact next request. [Inbox mutation](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-agent-loop/lib/index.js#L179-L207>), [send and status](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-agent-loop/lib/index.js#L793-L814>). `agent/status` uses the same non-awaited emit; the driver starts through `withInitiator` after setting running phase. [Driver wake](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-agent-loop/lib/index.js#L854-L869>).

### Session log notifications

`Session.append` commits a JSON snapshot; `session/event` observers are observe-only, contained per listener, and their returned promises are not awaited. Reentrant append while another append is being published throws `session append cannot reenter while another append is being published`. Consequently a `turn/start` or inbox-splice observer is not a supported async routing gate. Directly appending `model/selection` synchronously inside such an observer would also violate the reentrancy prohibition. The public async `selectModel` command is not claimed to append synchronously before its first await; starting that command in an observer still does not make the observer awaited. [Append contract and implementation](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-session/lib/index.js#L1480-L1537>), [publication/reentrancy](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-session/lib/index.js#L1563-L1598>), [observe-only invocation](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-session/lib/index.js#L1226-L1239>).

`session/created` also does not await listener promises. It occurs at publication, not each step. [Session announcement](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-session/lib/index.js#L1894-L1923>). `session/flush` is an awaited durability checkpoint, but its contract is storage settlement, not request selection; the actual pre-step path above does not call it before assembly. [Flush](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-session/lib/index.js#L1938-L1968>), [pre-step](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-agent-loop/lib/index.js#L902-L927>).

### Creation/setup and end-of-turn

There **is** an awaited `agent/created` serial lifecycle event. Public create/resume accept setup; native factory setup runs before publication, and publication awaits Agent announcement. Initialization is wrapped in maintenance. This is a legitimate place to install Agent-scoped contributors/middleware or initialize caller-owned state. It is not a per-step route decision event. [Public creation](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-agent/lib/index.js#L444-L471>), [setup and maintenance](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-agent-loop/lib/index.js#L1914-L1955>), [publication](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-agent-loop/lib/index.js#L1783-L1804>), [Agent announcement](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-agent/lib/index.js#L565-L590>).

`agent/turn-stopping` is awaited only after a step when the turn has an ending and no next-step inbox input. It is absent before the initial request and not dispatched for every tool-driven continuation. It cannot be renamed into a before-provider step hook. [Stopping dispatch and continuation](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-agent-loop/lib/index.js#L980-L1009>), [tool-driven step return](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-agent-loop/lib/index.js#L1163-L1167>).

## 3. Scoped middleware: supported ordering, limited timing

`createScope` returns a context with a scope tag and owned disposal boundary. `scopeTarget` admits untagged listeners and listeners tagged with the exact scope or an ancestor; it preserves a base filter. This is listener **admission**, not priority. Scoped registration does not by itself make a listener run before global listeners. [Scope creation](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-scope/lib/index.js#L288-L314>), [scope filtering](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-scope/lib/index.js#L315-L338>), [Cordis dispatch filtering](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/cordis/lib/index.js#L250-L264>).

Cordis `on` owns the listener on its fiber. Registration uses `unshift` for `prepend`, otherwise `push`; the waterfall calls admitted listeners outermost-first around the final callback, and a listener can veto by not calling `next()`. Returning from an outer wrapper after `await next()` can override an inner returned value. This is useful and supported **inside that event**; it does not wrap the calling `SystemPrompt.assemble` function's earlier work. [Registration API](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/cordis/lib/index.js#L360-L380>), [waterfall and insertion](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/cordis/lib/index.js#L308-L345>), [assembly call site](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-system-prompt/lib/index.js#L356-L405>).

Prompt registrations are a separate ordered store. Named/anonymous entries are insertion ordered; scope layers run farthest ancestor first, nearest scope last. Named merge permits nearest-scope shadowing, but variables are actually **evaluated** global-first then scope-chain-first before the waterfall. Section `order` sorts sections, not preceding variable/tool evaluation. [Entry storage](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-scope/lib/index.js#L8-L74>), [anonymous append](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-scope/lib/index.js#L85-L115>), [layer ordering/merge](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-scope/lib/index.js#L155-L180>), [assembly order](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-system-prompt/lib/index.js#L356-L398>).

### Variable-provider side effects are not the missing seam

`variable(name, provider)` registers a provider in the calling context's scope; it offers no middleware `next`, async admission result or priority/prepend argument. A scoped variable callback cannot run before already registered global variable callbacks. `assemble` does not await variable providers, tools providers, section-text functions or context-text functions. [Variable API](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-system-prompt/lib/index.js#L302-L312>), [evaluation](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-system-prompt/lib/index.js#L356-L398>), [context resolver](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-system-prompt/lib/index.js#L183-L189>).

A synchronous callback can of course perform JavaScript side effects. Under entirely controlled global registration order it might update plugin-owned state before later providers. That mechanical possibility is **not evidence** of a supported async, before-all-contributors native selection transaction: earlier globals may already have run, native selection state remains separately owned, and no accepted route snapshot is passed to all providers by this API. It would narrow the requirement to specially ordered/cooperating contributors rather than satisfy it. The conclusion is limited to that missing contract, not an assertion that all provider side effects are categorically forbidden.

## 4. Native selection ownership and coexistence

### What `installModelSelection` actually promises

The root Agent module exports `installModelSelection`. It takes caller-owned mutable selection state and installs three scoped listeners. At assembly-waterfall entry it reads `const selected = selection.current`, then awaits downstream listeners, assigns `selection.assembled = selected`, and overlays provider/model interpolation variables. The request listener waits for downstream results, reads `selection.assembled`, overrides provider/model, and clears inherited effort unless selected effort exists. A prepended pre-step listener uses that assembled selection to add a model-change notice. [Exact helper](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-agent/lib/index.js#L148-L210>), [root exports](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-agent/lib/index.js#L700-L702>).

The inline comment that prompt assembly snapshots selection “before delegating” describes **delegating within its assembly middleware**, not before registered providers. Its installation does not create a second, earlier assembly entry point. Mutating `selection.current` after that read does not replace the object reference already captured for the current step; replacing the current value is the concurrency pattern, not mutating the captured object in place. [Capture and application](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-agent/lib/index.js#L166-L191>), [provider-before-waterfall call](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-system-prompt/lib/index.js#L356-L398>).

### Who owns native Session selection

The Session-controller implementation constructs an `ApiSessionAgentController`, with its own selection WeakMap. Its `selectionFor(agent)` initializes a holder from the durable modelSelection projection once, then reads pending picked state, last request header or the deployment default. It installs `installModelSelection(agent.ctx, selection)` and retains that holder. `composeAgent` installs native selection before preset mounting for both ordinary composition paths. [Owner and map](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-api-session-controller/lib/index.js#L179-L198>), [holder](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-api-session-controller/lib/index.js#L269-L326>), [composition](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-api-session-controller/lib/index.js#L346-L364>), [controller construction](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-api-session-controller/lib/index.js#L2935-L2957>).

`ApiSessionAgentController` and its `selectionFor` / `selectForNextRequest` methods are **not root exports**. `SessionController` does have an ordinary JS `agents` field referencing it, so “not exported” must not be exaggerated into “physically inaccessible in JavaScript.” However, reaching through `sessionController.agents.selectionFor(...)` is accessing an internal collaborator, not evidence of a supported public pre-provider extension API. The inspected public exports and documented controller methods do not grant a transient per-step override capability or a timing hook through this field. The unavailable declarations leave the formal TypeScript visibility uncertain. [Internal class](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-api-session-controller/lib/index.js#L179-L185>), [field construction](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-api-session-controller/lib/index.js#L2935-L2957>), [public resolve/select methods](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-api-session-controller/lib/index.js#L3032-L3039>), [selection method](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-api-session-controller/lib/index.js#L3093-L3100>), [exports](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-api-session-controller/lib/index.js#L3364-L3367>).

Installing a **second** independent selection holder is not demonstrated coexistence: each helper can write assembly variables and request routes, while native notices still use the native holder's assembled selection. Because each wrapper applies its return override after `next()`, registration order can determine the winner without establishing shared ownership. A prepended late waterfall can override the result, but cannot correct already run providers or turn the two stores into one accepted selection transaction. [Selection listeners](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-agent/lib/index.js#L166-L204>), [Cordis ordering](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/cordis/lib/index.js#L308-L345>).

### Native public selection is durable user intent, not a transient route override

Public `SessionController.selectModel(request)` delegates to a command that resolves the Agent, serializes with image admission, validates/normalizes the requested model through LLM APIs, appends `model/selection`, updates the native holder and asynchronously calls `agentDefaultModel.saveSelection(selected)`. Therefore calling it for each concrete Auto route would have durable Session-selection semantics and default-save side effects; no `persist: false` or transient override option is present in the inspected implementation. [Public forwarding method](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-api-session-controller/lib/index.js#L3093-L3100>), [command](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-api-session-controller/lib/index.js#L788-L820>), [durable selection/cache update](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-api-session-controller/lib/index.js#L307-L325>).

The default save can be a no-op when no configuration entry/editor is mounted, but when those exist it queues `editor.edit` in submission order. The safe source conclusion is “requests default persistence,” not “always writes a profile.” [Default-model implementation](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-agent-default-model/lib/index.js#L46-L66>).

The modelSelection projection records `pending` on `model/selection`, derives `lastUsed` from request headers and clears pending only on exact provider/model/effort equality. The native execution cache likewise consumes only a matching header; the controller listens for `request/header` to do so. A late concrete redirect while pending intent is Auto must not be assumed to consume or correctly project that intent. Nor is simply appending `model/selection` proven equivalent to the native command: the live holder reads the projection on initial installation, while the native command separately updates `selection.current`. [Projection and equality](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-api-session-controller/lib/index.js#L2135-L2199>), [holder initialization and cache update](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-api-session-controller/lib/index.js#L274-L325>), [header consumption](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-api-session-controller/lib/index.js#L2997-L3004>).

## 5. Retry and resume boundaries

`step(decision)` renders the accepted prompt once **before** the request-attempt loop. Each attempt prepares the request, refreshes runtime context and builds/dispatches against the same accepted assembly/tools. A retry returned by `agent/request-error` uses `continue` in that attempt loop; it does not call `preStep`, re-evaluate variables/sections/tools or rerender the prompt. Consequently a route change in request-error/request middleware cannot claim fresh full-provider coherence on retry. [Prompt rendering and attempt loop](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-agent-loop/lib/index.js#L1043-L1088>), [retry continuation](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-agent-loop/lib/index.js#L1128-L1147>), [request proposal](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-agent-loop/lib/index.js#L1174-L1211>).

`refreshContext` deliberately re-evaluates registered runtime-context text at request admission while keeping accepted sections, tools and interpolation variables. Its inline contract expressly says those providers and the waterfall do not rerun. This refresh is not a general pre-provider model-selection hook or permission to manually reconstruct/rerender internal prompt state. [Refresh API and body](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-system-prompt/lib/index.js#L314-L345>).

Native resume obtains the preset composition and passes its setup to Agent resume; that composition installs the native holder. Generic loop resume reconstructs the Session and invokes the same setup-and-publication path with source `resume`. This gives lifecycle reinstallation, not a per-step route-resolution seam; the ordinary pre-step order remains unchanged afterwards. [Controller resume](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-api-session-controller/lib/index.js#L392-L403>), [composition](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-api-session-controller/lib/index.js#L351-L364>), [loop resume](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-agent-loop/lib/index.js#L1984-L2013>), [setup/publication](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-agent-loop/lib/index.js#L1914-L1955>).

## 6. Precise supported/unsupported boundary

Supported surfaces established by the inspected JS are: effect-owned scoped registration; synchronous prompt contributor callbacks; post-provider assembly transformation/veto; post-assembly pre-step admission; request-config middleware; creation/setup/announcement lifecycle; and explicit native durable model selection. Their timing and ownership contracts are the ones documented above, not a synthesized earlier hook. [Prompt APIs](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-system-prompt/lib/index.js#L245-L312>), [assembly](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-system-prompt/lib/index.js#L347-L405>), [pre-step](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-agent-loop/lib/index.js#L902-L927>), [request](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-agent-loop/lib/index.js#L1174-L1211>), [native public selection](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-api-session-controller/lib/index.js#L3093-L3100>).

Not established as a supported solution to this task: any guessed event name; async inbox/status/session observers as an admission barrier; a variable callback used as an ordered routing side channel; access through the controller's internal collaborator; two competing `installModelSelection` holders; overriding/method-wrapping `assemble` or loop methods; replacing host internals; or manually rerendering/reassembling after provider evaluation. Several are mechanically possible JavaScript techniques, but none supplies the required public contract in the examined call path. The task and repository constraints independently exclude host patching, monkeypatching and internal manual rerendering.
