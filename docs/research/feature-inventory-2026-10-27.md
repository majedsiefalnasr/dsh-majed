## How to read progress

- **Composed:** reachable through the production plugin entry under its documented activation conditions. This does not establish installation or operational success.
- **Controlled evidence:** temporary stores, synthetic account/pairing state and controlled transports; some probes load actual native host services. jsdom/presentation adapters remain fixtures, not browser geometry evidence.
- **Partial/dormant:** reusable implementation or bounded proof exists, but the required complete product path is absent, inactive or still fails a criterion.
- **Open verification:** a dedicated follow-up or release gate retains unproved visual/operational behavior. An implementation-only closure is not full acceptance.

There is no defensible overall completion percentage. Requirements differ in size, and neither passing test counts nor issue closure measures end-to-end delivery.

## Decisions for the next Owner discussion

This is an options list for design, not an implementation order or implied scope reduction:

1. Decide the next user-visible outcome: stabilize existing management paths, finish Codex as a usable provider, pursue deterministic Auto, or revise the product boundary. Reuse existing code/evidence where applicable rather than restarting from scratch.
2. Resolve substantive public-contract questions explicitly: Auto pre-provider coherence/shared retry enforcement; Skills standing-preset and warmed slash invalidation. A failing contract is not mere visual polish. Choose supported alternatives, an explicit revised requirement/deferral, or continued investigation with a bounded budget.
3. Decide the intended supported host version. The manifest allows rc.2+, while several complete production proofs cover rc.3 only.
4. Keep the UI/functional/operational acceptance layers distinct. Any later browser/host infrastructure extension needs a scoped acceptance reason and approval; the inventory authorizes none.
5. Preserve learning-source versus runtime-dependency boundaries. Existing external installed plugins may continue serving the user's app, but their tools/provider success does not count as integrated Majed success.
