# Research: subscription parity and opt-in Auto routing

Date: 2026-10-22. Research only: no implementation, installed-plugin changes, credential reads, profile changes, or live provider requests. The only artifact produced is this report. Scope: integrate all subscription capabilities into dsh-majed, replace the standalone package only after parity, and add a native-picker Auto entry backed by an explicitly opted-in, prioritized account/model pool.

## Executive conclusion

**Do not treat rate-limit failover as missing functionality.** Installed `dsh-plugin-subscriptions` 0.9.9 already implements account pools, pre-output failover, cooldowns, retry-after extraction, sticky priority and quota-aware strategies, independent account entries, and optional heterogeneous tiers. The new work is principally explicit opt-in semantics, a first-class Auto identity and management UI, clear priority policy, observability, and preservation of a substantial existing provider/tool feature set. Diagnose an actual failure before assuming a rewrite fixes it.

**A plugin-only design is feasible through public DSH extension points; no host patch is justified.** An `LlmAdapter` can advertise an Auto model, resolve conservative capabilities, bind preparation to a routing generation, and dispatch through owned account-aware adapters. Public provider registration is exclusive: the integrated plugin and standalone plugin must not register the same provider routes simultaneously. This is source-level feasibility, not a live verified implementation.

**Keep the failover boundary before the first non-usage stream chunk.** Do not stitch a second model onto a partial answer or blindly replay tool operations. The installed pool already applies this boundary. The host's separate request-retry layer can retry a failed streamed attempt; that is a new attempt, not seamless stream continuation, and must be tested and explained separately.

## Account fallback versus cross-model fallback

### Same provider, same model: already automatic

[pool-family.js:22–44](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/lib/providers/pool-family.js#L22-L44>) unions per-account catalogs by wire model ID. Shared IDs have multiple members; an account-only model stays bound to the account advertising it. This avoids asking a plan for a model it never listed. Automatic pooling is enabled by default, including a single-account pool in actual assembly: [index.js:11790–11858](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/lib/index.js#L11790-L11858>). The README's “needs ≥2 accounts” shorthand is not the exact implementation condition.

`accountAllowsPool` permits participation unless `poolEnabled === false`; an absent model allowlist permits every model: [account-preferences.js:26–28](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/lib/providers/account-preferences.js#L26-L28>). Independent `~account:` entries require `independentEntry === true`, validate the exact account/model, and do not fall back: [account-preferences.js:54–106](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/lib/providers/account-preferences.js#L54-L106>), [account-preferences.js:138–186](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/lib/providers/account-preferences.js#L138-L186>).

**User opt-in is a deliberate new policy:** importing an account or retaining an existing upstream pool preference must not silently enroll it in a new cross-provider Auto pool. Separate “available for direct/pinned use” from “consented for Auto”; define whether existing same-model routing keeps upstream behavior or also becomes opt-in. Do not disable direct model selection merely because Auto is empty.

### Cross-provider or cross-model: existing optional tier mechanism

Configured `tiers` are extra picker rows under the first member's provider and can contain heterogeneous provider/model members; they are not automatic. `families` instead ignores cross-provider members. [pool.js:90–133](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/lib/providers/pool.js#L90-L133>), [index.js:11838–11856](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/lib/index.js#L11838-L11856>), [README:261–266](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/README.md#L261-L266>).

An Auto entry can build on that concept, but needs its own stable provider/model identity, explicit per-member consent and order, account pinning, visibility, diagnostics and policy controls. Reusing a tier named `auto` under the first member's provider is possible but leaks ownership semantics and inherited retry policy into a supposedly neutral feature. A dedicated plugin-owned route is clearer.

### Priorities and quota semantics: important corrections

[pool.js:309–337](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/lib/providers/pool.js#L309-L337>) implements:

- `priority`: configured/default account order **except a healthy sticky session member moves first**. It is not strict “always highest priority on every turn.” After recovery, the highest-ranked member need not regain a session immediately.
- `quota_aware`: healthy members with telemetry are scored using remaining fraction/time until reset; a sticky member keeps the lead unless a challenger exceeds the `switchMargin` (default **2**). Copilot/unknown telemetry gets score zero. [pool-usage.js:57–80](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/lib/providers/pool-usage.js#L57-L80>), [pool-usage.js:178–222](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/lib/providers/pool-usage.js#L178-L222>).
- At **95%** used on any applicable window, members are marked quota-full, but selection appends them to a **last-resort tail** rather than excluding them. The README's “gated out” wording overstates enforcement. Health cooldowns, unlike quota percentages, actually exclude a candidate.
- Sticky memory is in process, bounded to **1,000** entries; usage snapshot TTL is **5 minutes**, pool assembly cache **5 seconds**. Quota-endpoint failures negatively cache provider retry-after or TTL; non-credential failures degrade to available/zero score. [pool.js:15–24](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/lib/providers/pool.js#L15-L24>), [pool.js:338–350](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/lib/providers/pool.js#L338-L350>), [pool-usage.js:13–17](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/lib/providers/pool-usage.js#L13-L17>), [pool-usage.js:140–204](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/lib/providers/pool-usage.js#L140-L204>).

Recommended initial Auto strategy: user-ordered priority with explicitly documented session stickiness; quota-aware scheduling can remain a separate opt-in advanced mode. Decide whether 95% is only a preference or a user-configurable hard ceiling.

## Existing failure classification, cooldown and waiting

### Member failover and cooldown

[pool-health.js:21–85](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/lib/providers/pool-health.js#L21-L85>) classifies stable `LlmError` codes:

- `RATE_LIMIT` / `QUOTA_EXCEEDED`: switch, cooldown `failure.providerRetryAfterMs` or **5 minutes**. Claude and Antigravity cool only the `(provider, account, model)` member; other providers cool the entire account, so sibling models cannot evade an account-level limit.
- `AUTH` / `INVALID_CREDENTIAL` / `MISSING_CREDENTIAL`: switch, account cooldown **24 hours**; auth changes clear health records.
- `SERVER` / `TIMEOUT` / `EMPTY_RESPONSE`: switch, member cooldown **60 seconds**.
- `TRANSPORT`: switch without a cooldown.
- `HTTP_402` / `HTTP_404`: switch with **60-second** member cooldown (plan/model entitlement may differ by account).
- Context overflow, `ABORTED`, other codes including ordinary 400, and non-`LlmError` exceptions: rethrow, no switch.

Health is in-memory; expiration allows a real request to prove recovery, not a background probe. Longer existing cooldown wins. [pool-health.js:89–158](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/lib/providers/pool-health.js#L89-L158>). Auth change invalidates catalog/pool/usage and clears image/chat health: [index.js:11559–11570](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/lib/index.js#L11559-L11570>).

When all candidates fail or cool down, the pool preserves the last actual failure code, status and request ID where available, plus earliest member-recovery retry hint scoped to this pool. It does **not** label every exhaustion as a rate limit. [pool.js:351–395](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/lib/providers/pool.js#L351-L395>).

### HTTP/reset parsing

[common.js:68–120](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/lib/providers/common.js#L68-L120>) maps 401/403 to `AUTH`, 429 to `RATE_LIMIT` **before quota-wording detection**, 408/504 to `TIMEOUT`, other 5xx to `SERVER`, context-shaped 400 to context overflow, otherwise `HTTP_<status>`. Provider-specific reset readers run only on 429. The provider's actual rejected-window signal wins over generic retry-after; on non-429 only genuine `retry-after` is considered.

- Claude: `anthropic-ratelimit-unified-reset` / `anthropic-ratelimit-unified-fallback-reset`, then body `resets_at`, `resetsAt`, `reset_at`, `retry_after`. Per-token/request rollover snapshots are deliberately excluded. [claude.js:28–50](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/lib/providers/claude.js#L28-L50>).
- Codex: body `resets_in_seconds`, `reset_after_seconds`, `resets_at`, `reset_at`; deliberately not `x-codex-*-reset-after-seconds` rollover snapshots. [codex.js:26–42](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/lib/providers/codex.js#L26-L42>).
- Grok: body `retry_after`, `retry_after_seconds`, `resets_at`, `reset_at`; deliberately not generic `x-ratelimit-reset-*` bucket snapshots. [grok.js:23–35](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/lib/providers/grok.js#L23-L35>).
- Antigravity: Google `quotaResetDelay` duration preferred to `quotaResetTimeStamp`. [common.js:121–145](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/lib/providers/common.js#L121-L145>).
- Copilot: generic retry-after, no separately verified provider-specific reset reader. [README:294](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/README.md#L294>).

Generic retry-after accepts seconds or HTTP date. Shared parser also understands durations and epoch forms for allowlisted provider fields, with explicit magnitude rules; it adds **2 seconds** grace and at least **1 second** wait. Numeric body values below 1e9 are interpreted as seconds, so an undocumented provider field changing units could misbehave. Unknown 429 reset signals log rate-limit-shaped headers and the first 200 body characters; error messages show up to 500 body characters. Preserve useful diagnostics but audit/redact raw upstream bodies before exposing new telemetry. [rate-limit.js:18–55](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/lib/providers/rate-limit.js#L18-L55>), [rate-limit.js:138–155](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/lib/providers/rate-limit.js#L138-L155>), [rate-limit.js:228–265](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/lib/providers/rate-limit.js#L228-L265>).

### Retry is a separate host plugin, finite by default

Subscription routes report policy; `@deepseek-ai/dsh-llm-retry` performs cancellable waiting. Package presence alone does not prove it is mounted in the user's composition (composition was intentionally not read). Without it, pool member failover still works, but exhausted-pool waiting does not. [README:268–296](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/README.md#L268-L296>).

Installed subscription defaults: **10 retries after the initial attempt**, initial delay **1,000 ms**, jitter **20%**, base cap **60,000 ms**, `rateLimit.wait: true`, max wait **6 hours**. Waiting mode raises the shared max-delay ceiling, including local transient backoff (last exponential interval can reach **512 seconds**). Out-of-ceiling provider waits are not clamped and retried prematurely. [rate-limit.js:268–337](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/lib/providers/rate-limit.js#L268-L337>).

Exact host retry implementation records retry state durably, resets it at step start/turn end, bounds normal retries by `maxRetries`, accepts a positive provider hint only within the policy max delay, and cancels waits on caller abort or plugin teardown. It registers on `agent/request-error`. [host retry:68–107](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-llm-retry/lib/index.js#L68-L107>), [host retry:116–183](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-llm-retry/lib/index.js#L116-L183>). The host also supports `mode: always`; do not choose that for Auto. Bound total Auto attempts across accounts and outer retries, not just retries per member, to prevent multiplicative latency/replay.

## Streaming, cancellation, replay and tool safety

- **Installed pool boundary:** buffers leading `usage`, treats empty/pre-output error finishes as failures, closes failed iterators, classifies and tries the next member. Once the first non-usage chunk is emitted, it remembers that member and passes every subsequent chunk/failure through without pool failover. Consumer early-return closes the concrete iterator. This boundary includes reasoning and tool deltas, not merely visible text. [pool.js:219–299](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/lib/providers/pool.js#L219-L299>).
- **Host request retries are distinct:** exact host loop persists `assistant/attempt` for terminal error/aborted finishes and invokes `agent/request-error`; a retry re-prepares the same step even if that failed attempt previously streamed partial output. Successful tool calls execute only after a successful assistant message is committed. Therefore the pool's no-midstream-switch rule does not imply “the host never reissues a partial model attempt.” Do not promise that. [host agent loop:1079–1167](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-agent-loop/lib/index.js#L1079-L1167>). Audit interactions with recovery middleware and non-chat tools separately before claiming no duplicate upstream work.
- **Cancel:** pool selection/attempts check caller abort; lookup waits can abort without cancelling shared catalog work. Provider stream watchdog chains the caller signal; fetch failure maps caller abort to `ABORTED`, idle timeout to `TIMEOUT`. [pool.js:219–255](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/lib/providers/pool.js#L219-L255>), [common.js:165–212](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/lib/providers/common.js#L165-L212>), [common.js:367–400](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/lib/providers/common.js#L367-L400>). A future router must not convert abort into a reason to try another provider.
- **Credential refresh:** one per-account TokenManager coalesces refresh; a revoked account removes itself, not siblings. A concurrent new login prevents deletion of its newer refresh token. Codex/Claude streams perform one forced refresh/retry on 401. [accounts.js:57–135](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/lib/providers/accounts.js#L57-L135>), [common.js:313–364](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/lib/providers/common.js#L313-L364>), [codex.js:876–901](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/lib/providers/codex.js#L876-L901>), [claude.js:637–661](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/lib/providers/claude.js#L637-L661>). Do not execute these modules just to inspect metadata: normal operation can refresh/remove stored auth or sync Claude Code credentials.
- **Opaque history:** subscription replay is bound to a hash of concrete provider/account/model; mismatches discard replay state rather than sending another account's signed/opaque state. [replay.js:1–37](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/lib/providers/replay.js#L1-L37>). The host separately strips replay across adapter ownership changes: [host llm:2267–2288](</Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-llm/lib/index.js#L2267-L2288>). Preserve normalized tool-call/result history while excluding incompatible signatures and private continuation state.
- **Media/tools are not chat:** image scheduling uses independent health and only fails over on definitive auth/quota/entitlement rejections; ambiguous transport, timeout and 5xx are not resent because an image might already have been generated. One 401 refresh/retry is permitted. It does not obey chat account allowlists/tiers/quota ranking. [image-pool.js:18–87](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/lib/providers/image-pool.js#L18-L87>). Preserve this separation and explicitly define whether Auto consent applies to tools. Do not generalize chat replay to async video submission, image generation, reset-credit redemption, or user tools with side effects.

### Capability envelope and remaining design traps

Installed pool resolution intersects reasoning effort IDs and modalities and takes the minimum known context/output caps across resolved members: [pool.js:155–210](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/lib/providers/pool.js#L155-L210>), [pool.js:422–445](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/lib/providers/pool.js#L422-L445>). However, unknown context limits are filtered out; an empty modality intersection becomes `undefined` (unknown), not an explicit rejection. This is not proof that every heterogeneous pool request is valid. A new Auto route must reject/filter incompatible candidates before dispatch, advertise an honest conservative envelope, and test long histories, images, tools, effort, max tokens, tool-update semantics and system-prompt update semantics.

Using `ctx.llm.stream()` recursively for each child member normalizes throws into terminal finish chunks and applies middleware again. A router must handle both terminal error chunks and exceptions and avoid re-entering its own Auto route. Existing internal account-aware dispatch plus its replay wrapper is the better integration boundary when the provider source is vendored.

Host history records the public requested alias; reporting a concrete serving account/model requires sanitized plugin observability. Keep Auto selected while displaying “served by …” and reason for failover without mutating user model selection behind their back or revealing account identifiers unnecessarily.

## Recommended scope and safe replacement plan

### Scope recommendation

Prefer a **pinned, attributed source integration with preserved modules and tests**, not a clean-room rewrite of every OAuth/wire/media subsystem. Add a narrow Auto routing/settings layer after characterizing upstream behavior. Keep upstream differences reviewable and plan an update process for fast-changing provider endpoints. Preserve the standalone plugin until this integrated capability matrix passes. The npm package exports only its top-level host/client faces, not a stable public account-pool integration API: [package.json:24–35](</Users/majedsiefalnasr/.dsh/profiles/desktop/node_modules/dsh-plugin-subscriptions/package.json#L24-L35>). Simply depending on and mounting it from dsh-majed would not truly replace its maintenance/state responsibilities and cannot safely coexist with its own duplicate route registrations.

### Phased replacement, each with an explicit gate

1. **Characterize and pin.** Fetch upstream at the published commit; verify tarball/source provenance and inspect all third-party notices/dependencies. Add the MIT notice and source/version attribution to the project's notices. Inventory every provider, RPC, browser component, tool name/alias, saved preference, catalog, media path and history format. Port relevant upstream tests before adding new routing behavior.
2. **Build isolated parity.** Keep feature code disabled by default and test with synthetic accounts/provider responses in an isolated DSH composition. Preserve public provider/model IDs and legacy replay decoding. Verify the actual 0.2.1-rc.2 host API and browser UI, not just 0.2.0-rc.2 assumptions. Do not mount integrated and standalone copies under the same provider/tool/RPC IDs.
3. **Add opt-in Auto.** Introduce explicit account/model membership and order; no implicit enrollment on login/import, no inferred cross-provider consent, and no unrelated API-key providers in the pool unless separately authorized. Define strict versus sticky priority, eligible-model/capability constraints, hard versus advisory quota limits, bounded retries/waits, and sanitized reason/account/model diagnostics. Show Auto in the native catalog and a clear empty-pool state.
4. **Test failure boundaries.** Synthetic cases: 429 with body/header/date reset; unknown reset; 401 refresh/revocation; model/account quota scopes; all cooling; no telemetry; stale usage; empty streams; partial reasoning/text/tool deltas; consumer return; abort during selection/fetch/wait; provider shutdown; opaque replay across accounts/models; incompatible context/images/effort; concurrent settings changes. Separately test tool-policy history and image/video/reset-credit non-replay rules. Include combined pool-attempt × outer-retry budget tests.
5. **Read-only migration preview and consent.** New integration should initially display a non-secret migration plan and require approval before reading/migrating sensitive credential state in normal product operation. Preserve tokens via approved migration or explicit reauthentication without copying them into the repository/logs/browser. Existing source can mutate state on normal loads (legacy migration/refresh), so do not import/execute it in research. Define a single writer and pause in-flight requests before cutover; two copies must never concurrently rotate shared refresh tokens.
6. **User-approved cutover only after parity.** Back up approved state/config safely; disable the standalone registration, enable integrated registration, restart host, verify native picker, direct/pinned/Auto routes, usage, attachments/tools and restart persistence. Retain the old package and compatible state until rollback has been proven; do not delete credentials or uninstall automatically. Rollback disables integrated ownership before restoring standalone ownership. Any schema change needs a reversible migration or explicit compatibility plan.

## What a reported rate-limit problem could actually be

Without examining user state or running live calls, plausible causes include: only one eligible account for that exact model; opted-out/allowlisted/pinned accounts; incorrect manual account reference; all alternatives cooling; a provider error code outside the switch classifier; the failure arriving after the first non-usage chunk; a new reset-header/body shape; known provider plan eligibility; unsupported host-version behavior; or missing mounted host retry plugin when waiting rather than switching is expected. These are hypotheses, not diagnoses. Collect redacted provider/code/status, routing eligibility, attempt phase, cooldown and reset metadata before choosing a fix. Never request raw tokens, credential files or unredacted HTTP bodies.
