# E09 evidence: honest copy-on-select and native page reading (2026-10-28)

Ticket #89 (spec stories 25 and 27). Branch `impl/e09-copy-read`, based on integration `19715281edadba8b70c351f447c4069e21ed8d16`. Evidence is from controlled jsdom tests against the built client (`dist/client.js`), Node v23.11.0, jsdom 26.1.0, React 19.2.0. It is not evidence of a real browser, OS clipboard permission, native mobile selection, an installed DSH host or paired use.

## Change

- `client.js` `startAutoCopy` now reports an outcome (`copied`, `error`, `unsupported`) instead of staying silent. Success is reported only after `navigator.clipboard.writeText` resolves or the `document.execCommand('copy')` fallback returns `true`.
- A rejected write whose fallback also fails reports `error`. A missing clipboard API whose fallback fails or throws reports `unsupported`.
- New locale keys `copy.error` ("Could not copy the selection") and `copy.unsupported` ("Copying is not available here"), written in English in both the `en` and `zh` dictionaries; `ar` inherits `en`.
- The shared toast keeps `role="status"` and `aria-live="polite"`; error feedback sets `data-tone="error"` and an error glyph, reset on the next success.
- The stop function marks the watcher as stopped, so a clipboard promise settling after disposal or after switching the setting off shows nothing. Previously such a late result invoked the localizer after the dictionary was withdrawn.
- Unchanged: default off, exclusion of input/textarea/select, contenteditable composer and `.xterm`, collapsed/whitespace selections, duplicate suppression, 30 ms debounce, native mobile selection (the client adds no selection handles or touch handlers, only `mouseup`, `dblclick` and `keyup` listeners).

## Existing read-page regressions (not modified)

`lib/read-page-native.js` and `test/read-page-native.test.js` already cover the spec line 196 reading contract; all 22 tests pass unchanged. Coverage relevant to story 27:

- Delegation to the native fetch tool with the outer call's signal; cancellation (`controller.abort()`) fails closed and in-flight cancellation is forwarded; native denial, native errors and a missing native contract propagate with zero fallback invocations (no cloud/original fallback).
- The output carries raw fetched text, an empty `summary`, no links, and a warning that no AI summary or focused extraction was generated; a supplied `query` is not forwarded to the fetch and is disclosed as not processed.
- Content is bounded to `MAX_CONTENT_CHARS` (60,000) with a truncation warning.
- Content is prefixed with an untrusted-data notice and an uncertainty entry marks it as external evidence, not instructions.
- Malformed native output fails closed; unrelated tools delegate unchanged; disposal removes the hook.

No concrete gap against spec line 196 was found, so nothing was added there.

## Limitations and deferred items

- Browser clipboard permission and user-gesture rules, the `execCommand` fallback in real browsers, and the toast's visual rendering are unverified; the clipboard and `execCommand` are test doubles and jsdom performs no layout.
- Native mobile selection controls are preserved by not touching selection or adding handles, but this is unverified on a real device. Mobile testing is deferred to the Owner after publication.
- Paired-remote behavior, installed DSH host behavior and real assistive-technology announcements are unverified.
- Selection changes made without `mouseup`, `dblclick` or Shift/A `keyup` (e.g. touch-handle drags) never trigger a copy; this is existing behavior and was left unchanged.
- No localization beyond English was added for the new strings (the `zh` dictionary carries English values per the English-only project-content rule).
- This is not full E09 acceptance: the ticket's browser evidence, accessibility checks and paired scenarios remain separate.
