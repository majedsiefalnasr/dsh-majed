# R02 Codex direct workflow evidence

Production implementation increment for [R02 / #55](https://github.com/majedsiefalnasr/dsh-majed/issues/55). Real provider login/consumption, browser visual acceptance and full subscription parity remain separate gates.

The production root's Codex management composition now owns an explicit model-runtime toggle independently of account management. Login alone never registers a provider or enrolls Auto. Enabling the runtime composes the real R01 protected account/refresh service, private catalog/preferences store, source-backed catalog/Responses adapter and public native LLM registration. Disable/unload disposes registration and cancels runtime work. No reference plugin is loaded or reference store accessed. The source pin, adapted compiled files and notices are in `modules/subscriptions/codex/PROVENANCE.md` and `upstream/UPSTREAM.json`.

Native Settings exposes provider-catalog refresh; display names, visibility, supported effort defaults, context budgets and Standard/Fast settings; independent per-account IDs/aliases; and manual model entries. Catalogs and preferences persist separately from credentials. Discovered account-specific capabilities take precedence, durable account-specific caches and the reviewed static model list provide labelled fallback, and unknown manual/unlisted capabilities remain absent. Explicit request effort wins. Native `prepareCall` binds the actual serving account before header/capability preparation; subsequent account removal or independent-entry revocation fails rather than selecting a different account.

`npm test` includes controlled protected-account/direct runtime and rendered English/Arabic Settings suites. `node scripts/test-settings-product.mjs --codex-direct`, with the same four source/dependency environment pointers documented for R01, additionally runs against installed DSH `0.2.1-rc.3` / Node `v24.21.0`. It mounts the actual production host entry and browser bundle in actual native Settings, logs in through controlled OAuth and physical paired-remote Fetch/RPC, restarts the service and reloads the private temporary account, refreshes credentials, and separately enables Codex models. It feeds actual registered native LLM metadata into the unmodified native ModelDirectory with a fixture-owned session projection, selects a model/explicit effort, calls the actual native LLM prepared-call API and consumes the source-backed direct stream. Disable/re-enable retains exactly one registration. Missing local cookie/remote pairing reject. All four owned listeners close, and the report emits native/source hashes.

The native picker boundary uses the actual native ModelDirectory with fixture session/catalog projections; no picker option is fabricated, and the projected catalog comes from the real registered adapter. This proves selection-to-prepared-dispatch coherence at that public seam. It does not prove actual native session persistence, browser picker layout/keyboard geometry, real desktop/remote live use, or model quality. jsdom/presentation adapters remain explicit limitations. Search, image/video workflows and quota/reset operations remain their own tickets; no full provider parity is inferred from chat.
